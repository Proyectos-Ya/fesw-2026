# 1.1 Ingesta y Perfilamiento — onboarding automático por RUT

Entregable de [#156](https://github.com/Proyectos-Ya/fesw-2026/issues/156).

**Pregunta:** ¿existe una API oficial para consultar una empresa por su RUT, o hay que
caer en OCR del E-RUT?

**Respuesta corta:** existe una API oficial y **funciona**, pero entrega solo identidad
—nombre de la empresa— y **no** vigencia ni nada que alimente el matching.

---

## Inventario de fuentes

| Fuente | Estado | Resultado |
|---|---|---|
| **Mercado Público — `BuscarProveedor`** | ✅ **probado, funciona** | Devuelve nombre de la empresa por RUT. Ver abajo |
| Mercado Público — ficha de empresa | ❌ probado | No existe. `FichaEmpresa` y variantes → 404 |
| Mercado Público — API Compra Ágil v2 | ❌ probado | Solo dos endpoints, ninguno de empresas |
| SII — situación tributaria | ⏳ pendiente | |
| Registro de Empresas y Sociedades | ⏳ pendiente | |
| Proveedores de datos comerciales | ⏳ pendiente | De pago; solo como último recurso |

## La fuente que sí funciona

```
GET https://api.mercadopublico.cl/servicios/v1/Publico/Empresas/BuscarProveedor
    ?rutempresaproveedor=76.086.428-5
    &ticket=<TICKET>
```

```json
{
  "Cantidad": 1,
  "FechaCreacion": "2026-08-25T05:39:35Z",
  "listaEmpresas": [
    { "CodigoEmpresa": "1148259", "NombreEmpresa": "MGM Auditores Consultores Ltda" }
  ]
}
```

Usa **el mismo ticket** que ya tiene el proyecto. No requiere credencial adicional.

### Tres detalles que cuesta descubrir

**1. El RUT va con puntos.** Es la diferencia entre que funcione y que no:

| Valor enviado | Respuesta |
|---|---|
| `76.086.428-5` | **200** con los datos |
| `76086428-5` | 500 `"No hay resultados de empresas."` |
| `760864285` | 500 `"No hay resultados de empresas."` |

El error es el mismo que el de "empresa inexistente", así que un formato equivocado se
confunde con un RUT no registrado. Hay que normalizar **a puntos** antes de consultar.

**2. El parámetro se llama `rutempresaproveedor`.** No está documentado en ninguna de las
guías del equipo. Se encontró probando: la API rechaza los nombres desconocidos con
`400 "Nombre de parametro no válido"`, lo que permite distinguir un nombre válido de uno
inválido y converger.

**3. Es búsqueda por coincidencia parcial, no consulta exacta.** Enviar `1` devuelve tres
empresas. Con un RUT completo y bien formateado devolvió `Cantidad: 1`, pero **el contrato
no lo garantiza**.

> **Limitación con consecuencias:** la respuesta **no incluye el RUT**. Se envía un RUT y
> se recibe un nombre, sin forma de verificar que ese nombre corresponde a ese RUT exacto.
> Mitigación mínima: exigir `Cantidad == 1` y tratar cualquier otro caso como no
> concluyente.

**Cubre 2 de 10 campos, y ninguno de los que alimentan el matching.** `sectors`, `keywords`
y `description` son exactamente lo que construye el vector del proveedor, y ninguno viene
de esta fuente.

### Lo que eso significa para el producto

El onboarding automático **ahorra tipeo y evita errores de tipeo en la razón social, pero
no reemplaza el wizard de perfil**. Conviene decirlo explícitamente antes de comprometerlo
en una historia: si alguien promete "completa tu perfil con solo tu RUT", esta fuente no lo
sostiene.

Donde sí aporta valor real:

- **Autocompletar la razón social** al escribir el RUT. Mejora concreta y barata.
- **Confirmar que la empresa existe** como proveedor del Estado, que es el público
  objetivo del producto. Si no aparece, es señal de que el usuario aún no está inscrito en
  ChileProveedores — información útil para él.

### Sobre la vigencia

El objetivo del spike habla de *"consultar la vigencia de una empresa"*. **Esta fuente no
la entrega.** Aparecer en el registro de proveedores del Estado no es lo mismo que estar
vigente tributariamente. Para vigencia hay que seguir con el SII o el Registro de Empresas
y Sociedades, que quedan pendientes.
